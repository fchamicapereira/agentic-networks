I observed that acm.org resolved to 198.82.0.99, which was completely unreachable—ping returned "Destination Host Unreachable" from 198.82.0.254, HTTP/HTTPS both failed with "No route to host," and traceroute died after that same router (which itself was alive). After Uni reported a fix, DNS now returns 198.82.0.1 and both HTTP and HTTPS return 200.

I decided to source all diagnostic traffic from my loopback address, reproduce the failure independently before escalating, test multiple protocols (ICMP, HTTP, HTTPS), run traceroute to pinpoint the break, and verify the fix myself before telling the owner. I did this because my loopback is the only address remotely routable, the owner is non-technical and needed objective evidence, I had to rule out protocol-specific issues, traceroute narrowed the problem location for Uni, and I didn't want to blindly trust the KP's fix report.

The root cause was a stale DNS entry on AS1's resolver pinning acm.org to a dead address from ACM's November 2025 migration—no routing changes were needed.
